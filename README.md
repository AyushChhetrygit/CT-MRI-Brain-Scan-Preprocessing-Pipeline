# 🧠 CT / MRI Brain Scan Preprocessing Pipeline

A robust, end-to-end medical image preprocessing pipeline for preparing **CT** and **MRI** brain scan datasets — including their segmentation masks — for deep learning model training.

Built using the **JUH MR-CT Unpaired Brain Dataset** (Jordan University Hospital), this pipeline handles raw DICOM and NIfTI medical files, normalizes them using clinically appropriate methods, extracts 2D axial slices, and organizes the output into a clean train/val/test split ready for supervised segmentation models such as U-Net.

## Overview

In clinical environments, raw medical imaging data is complex, heterogeneous, and not directly consumable by machine learning models. This pipeline solves that problem by:

- **Discovering** all valid DICOM (`.dcm`) and NIfTI (`.nii`, `.nii.gz`) files recursively
- **Validating** each file against structural integrity checks (empty, NaN, Inf, bad dimensions)
- **Normalizing** CT scans using Hounsfield Unit (HU) windowing and MRI scans using percentile clipping
- **Extracting** valid 2D axial slices while filtering empty background frames
- **Resizing** all slices to a uniform `256 × 256` spatial resolution
- **Splitting** volumes at the patient level (70% train / 15% val / 15% test) to prevent data leakage
- **Saving** outputs as lossless `.npy` arrays alongside a paired image-mask manifest CSV

## Pipeline Stages

```
Raw Dataset (DICOM / NIfTI)
        │
        ▼
① File Discovery       →  Recursive scan, file-type filtering, junk removal
        │
        ▼
② Validation & Load    →  Structural checks: NaN, Inf, empty, bad dimensions
        │
        ▼
③ Preprocessing
   ├── CT  → HU Windowing  (center=40, width=80) + Min-Max normalization [0,1]
   └── MRI → Percentile Clipping (1st–99th percentile, background excluded) + normalization [0,1]
        │
        ▼
④ Slice Extraction     →  3D → 2D, filter empty slices (< 2% brain tissue)
        │
        ▼
⑤ Resize               →  Bilinear (images) / Nearest-Neighbor (masks) → 256×256
        │
        ▼
⑥ Patient-Level Split  →  70% train / 15% val / 15% test (seeded, reproducible)
        │
        ▼
⑦ Save                 →  .npy arrays (lossless, float32 for images / uint8 for masks)
        │
        ▼
⑧ Manifest & QC        →  dataset_manifest.csv + qc_report.csv
```

## Configuration

All pipeline parameters are centralized in the `CONFIG` dictionary at the top of `main_program.ipynb`. Edit this block to customize the pipeline for your own dataset:

```python
CONFIG = {
    # Input paths
    "ct_path":       "path/to/CT/images",
    "mri_path":      "path/to/MRI/images",
    "ct_mask_root":  "path/to/CT/masks",
    "mri_mask_root": "path/to/MRI/masks",

    # Output path
    "output_root":   "path/to/output/dataset",

    # CT windowing (Hounsfield Units — soft-tissue brain window)
    "ct_window_center": 40,       # Center HU value
    "ct_window_width":  80,       # Width of the HU window

    # MRI intensity normalization (percentile clipping)
    "mri_clip_low":  1.0,         # Bottom percentile to discard
    "mri_clip_high": 99.0,        # Top percentile to discard

    # Slice settings
    "target_size":         (256, 256),   # Output (H, W) per slice
    "min_brain_fraction":  0.02,         # Skip slices with < 2% tissue

    # Dataset split
    "split_ratios": {"train": 0.70, "val": 0.15, "test": 0.15},
    "seed":         42,           # Random seed for reproducibility

    # Storage format
    "save_format":  "npy",        # "npy" (lossless) or "png"
}
```

## Output

### `dataset_manifest.csv`
A CSV file with one row per saved 2D slice. Used directly as the input to a PyTorch / TensorFlow DataLoader.

| `subject_id` | Unique patient volume identifier |

## Quality Control

The pipeline implements **5 layers of data validation** before any file is processed:

| Check | What it catches |
|---|---|
| File size < 512 bytes | Truncated or empty placeholder files |
| `data.size == 0` | Arrays with zero elements |
| `np.all(data == 0)` | Completely black (scanner failure) images |
| `np.any(np.isnan(data))` | Missing or undefined pixel values |
| `np.any(np.isinf(data))` | Pixel values saturating to infinity |
| `data.ndim not in (2,3,4)` | Structurally corrupt arrays |
| `mask` in image root path | Mask/image cross-contamination guard |

## Key Design Decisions

### Patient-Level Splitting (Prevents Data Leakage)
Dataset splitting is performed on **3D patient volumes**, not individual 2D slices. This ensures that no slices from the same patient appear in both the training and test sets — a critical requirement for valid model evaluation.

### CT vs. MRI Normalization Strategy
| Modality | Method | Reason |
|---|---|---|
| **CT** | Fixed HU Window (center=40, width=80) | CT has a standardized physical scale (Hounsfield Units) across all scanners |
| **MRI** | Percentile Clipping (1%–99%) | MRI intensities are scanner-dependent with no physical standard |

### Interpolation Choice for Resizing
| Data Type | Interpolation | Reason |
|---|---|---|
| **Scan Images** | Bilinear (`cv2.INTER_LINEAR`) | Smooth blending preserves anatomical gradient detail |
| **Segmentation Masks** | Nearest-Neighbor (`cv2.INTER_NEAREST`) | Prevents label blending at boundaries between integer class values |

### `.npy` Format over `.png`/`.jpg`
Saves preprocessed slices as binary NumPy arrays (`float32` for images, `uint8` for masks) rather than standard image formats, preserving the full 32-bit floating-point precision of clinical measurements without lossy compression artifacts.
